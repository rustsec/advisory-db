# Unbounded decompression can exhaust memory and CPU resources

The `encoding::Decoder` stream can expand compressed input into a large output
buffer before a caller can enforce its body size limit. An attacker who controls
a compressed request or response can cause excessive memory allocation and CPU
use, resulting in denial of service.

This affects applications that decode untrusted gzip, deflate, Brotli, or Zstandard
bodies with the corresponding compression feature enabled.

Upgrade to actix-http 3.20.1 or later and configure `Decoder::limit()` when using
the decoder directly. Actix Web users must also upgrade to actix-web 4.18.2 or
later so that extractors pass their limits to the decoder.
