# Command injection in `vaultic ci export` through secret values

`vaultic ci export --format github` and `--format gitlab` print secrets as shell
commands that are meant to be run with `eval "$(vaultic ci export ...)"`. Affected
versions put secret values inside double-quoted `echo` and `export` lines without
escaping them.

As a result, a value containing `$(...)` or backticks ran as a command on the CI
runner when the output was passed to `eval`. A value containing a newline could
also add extra variables to `$GITHUB_ENV`, such as `NODE_OPTIONS` or
`LD_PRELOAD`. Encrypting a value only needs the recipients' public keys, which
are committed to the repository. So anyone who can get a modified encrypted
environment file into a branch whose CI job holds the private key can run code
in that job.

The flaw was fixed in 1.4.3. Values are now single-quoted, multi-line values
use GitHub's `KEY<<DELIMITER` syntax with a delimiter that cannot appear in the
value, and variable names must be valid shell identifiers. `--format generic`
is not affected, because its output is not meant to be passed to `eval`.
