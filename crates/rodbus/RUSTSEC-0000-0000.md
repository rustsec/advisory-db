# Unauthenticated peers can make the TCP and TLS server unavailable

A peer that opens connections to a Modbus TCP or TLS server can deny service
to its clients. Connections that never finish their TLS handshake, or that
stop reading replies, keep their sessions indefinitely and are counted toward
the session limit before the handshake, so unauthenticated connections evict
authenticated sessions and the sockets held grow with the attacker. An error
from accepting a connection, such as running out of file descriptors, ends the
server's task. The server stops accepting connections until the application
recreates it.

The connections need no authentication: a TLS server is reachable before the
handshake, and a plain TCP server accepts them from anyone. The consequence
depends on how the application runs the server: the library spawns the server
on the runtime, so clients and other servers in the process keep running, while
an application that runs the server future itself sees it end there.

Version 1.6.0 runs each TLS handshake under a timeout before the connection
counts as a session, ends evicted sessions wherever they are waiting, and keeps
accepting after an error. There is no workaround; upgrade to 1.6.0.
