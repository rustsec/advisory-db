# Empty side-band packets can panic during fetch

gix-packetline removes a trailing newline from side-band text by indexing the final byte without checking whether the payload is empty. A progress or error packet containing only its band designator therefore panics when its empty payload is converted to text. Direct decoding of empty side-band data also indexes a missing band byte.

A malicious Git server can send these packets while an application clones or fetches, interrupting the operation. An application that does not catch the panic can terminate. The demonstrated network path does not require server authentication, but still requires a workflow that contacts the attacker-controlled remote; process termination is not unconditional for every library caller.

Update to gix-packetline 0.21.5 or later. The fix handles empty text without indexing, rejects missing band designators as protocol errors, and guards undersized buffers in packet readers.

Reported by GitHub user `KutalVolkan`.
