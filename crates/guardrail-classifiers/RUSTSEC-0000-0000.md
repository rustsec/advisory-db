# Unbounded memory use when an ONNX stage tokenizes over-long input

With the `onnx` feature, the `onnx_injection` and `toxicity` stages
tokenized all of a request's text, however long, and nothing limited how
many requests were tokenized at once. A 10 MiB message took about 3.5 s
and 0.8 GB of memory before it was refused, and 16 at once raised the
proxy's memory by about 12 GB, so a client sending large request bodies
could run it out of memory.

From 0.4.0 a stage tokenizes at most as much input as could fit its window
limit (196 KiB at the default 16 windows) and treats anything longer as
over the limit, before taking an inference session.

Only builds with the `onnx` feature and an ONNX stage enabled are affected.
