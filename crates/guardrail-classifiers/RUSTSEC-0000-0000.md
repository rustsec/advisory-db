# Non-ASCII text makes PII redaction about 100 times slower on async worker threads

`PiiRedactor`'s patterns for card numbers, SSNs, IP addresses and AWS keys
used Unicode word boundaries (`\b`), which the `regex` crate can't search
with its lazy DFA once the text contains a non-ASCII character; it falls
back to an engine about 100 times slower (about 0.2 s of CPU per MiB). The
stage is on by default and runs on the async runtime's worker threads, so
as many large non-ASCII requests in flight as there are worker threads
stall every other request through the proxy. On 2 CPUs, two 10 MiB requests
stalled health checks for over 2 s.

From 0.4.0 the patterns use ASCII word boundaries and ASCII digits. The
same release also refuses custom `regex_injection` rules that the lazy DFA
can't search (in `guardrail-config`), since one such rule slows the whole
injection rule set the same way.
