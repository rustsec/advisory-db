# HTTP redirects can forward credentials to a different authority

The curl HTTP backend records the effective base URL after the initial smart-HTTP request and uses it for subsequent requests. Basic-authentication checks still examine the original URL, so credentials can be added to a new request sent to a redirected host. The same mismatch can allow credentials to be sent over HTTP after an HTTPS-to-HTTP redirect.

The attacker must control a redirect returned by the contacted server and provide a valid Git protocol response so the authenticated operation continues. A victim that clones or fetches with credentials using the curl backend can then disclose those credentials. Their subsequent use depends on the permissions they confer.

The source’s reqwest host check prevents its demonstrated cross-host vector, but checks only the host and does not establish protection against every authority or scheme change. `gix-transport` 0.56.0 validates redirect host, effective port, and scheme before reusing authentication in the shared redirect handling and the reqwest policy, allowing a same-host HTTP-to-HTTPS upgrade while rejecting downgrades. Upgrade to 0.56.0 or newer.

Reported by [sammiee5311](https://github.com/sammiee5311).
