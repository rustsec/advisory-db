# Control bytes in git-daemon requests can inject protocol parameters

The shared git-daemon request serializer copied repository paths and virtual-host strings into the request without rejecting NUL or line-feed bytes. An untrusted path containing NUL could introduce additional NUL-delimited protocol parameters, including a `host=` field, and a line feed could alter the framing interpreted by a daemon.

Exposure requires a caller to use attacker-controlled URL/path data with the `git://` transport. The demonstrated primitive changes request contents and can affect virtual-host/repository selection depending on daemon behavior; the advisory does not establish arbitrary command execution or credential theft through this unauthenticated transport.

Version 0.59.2 rejects NUL and line feed in both components before writing the request, in the shared blocking and async serializer. Its regression tests require an invalid request to produce no output. Carriage return is not treated as a protocol delimiter by this fix.

Reported by zx (Jace; @manus-use).
