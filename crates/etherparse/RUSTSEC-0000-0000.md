# Out-of-bounds read when iterating over IPv6 extension headers of laxly parsed packets

Iterating over malformed or truncated IPv6 extension headers can cause
out-of-bounds reads when the packet was parsed using one of the lax parsing
functions (e.g. via `Ipv6ExtensionsSlice::from_slice_lax` or `LaxSlicedPacket`).

Lax parsing stops at the first invalid or truncated extension header and returns
the headers parsed up to that point. The "next header" field of the last returned
header can then refer to a header that is not part of the slice.
`Ipv6ExtensionSliceIter` followed it without checking the remaining length.

A crafted or truncated IPv6 packet can cause a crash or expose memory located
behind the packet to the application. Users who do not iterate over the IPv6
extension headers of laxly parsed packets are not affected.

As a workaround, do not iterate over the IPv6 extension headers if lax parsing
reported an error.
