# Timed-out requests keep analysing, so slow inputs exhaust `bca-web`

`bca-web` answers a request that runs past its parse deadline with
`504`, but before 2.6.0 the request's analysis kept running on a
blocking thread. Once `max(threads × 2, 4)` such orphaned tasks existed,
the server answered `503` to every new request until they finished.
Some inputs parse in superlinear time (the pinned Perl grammar takes
minutes over a few tens of KB of `-and =>` pairs), so a handful of
small requests kept the server out of service for minutes. With the
deadline disabled, nothing bounded that work.

Fixed in 2.6.0: a request's parse and AST export stop at its deadline,
and earlier when a connection reset makes actix drop the request's
handler. An ordinary close does not stop the work before the deadline.
