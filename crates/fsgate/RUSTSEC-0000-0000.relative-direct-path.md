# `fsgate-broker`: a relative `--direct` path resolves against the working directory

`fsgate-broker --direct <path>:<rights>` lets the confined worker reach a path itself, without asking the broker. `--grant` refuses a relative path, but `--direct` accepted one and resolved it against the broker's working directory. So `--direct .:r` under a service started in `/` gave the confined worker, and every program it starts, read access to the whole filesystem, with no audit event.

Only `fsgate-broker` on Linux with a relative `--direct` path is affected. On macOS, 0.3.0 cannot confine a worker and exits instead. `--direct` first shipped in 0.3.0.

The flaw was corrected in 0.4.0: `--direct` refuses a path that is not absolute, with a usage error, before any worker starts.
