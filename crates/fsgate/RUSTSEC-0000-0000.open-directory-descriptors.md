# `Gate::open` returns directory descriptors, so a brokered worker can list without `LIST`

`Gate::open` needs only `Rights::READ`, but it opened any path beneath a grant, including a directory, and the broker delivered the resulting descriptor to its worker. A worker holding `READ` without `LIST` could list that directory and open paths relative to the descriptor under its own authority.

Under Landlock, the worker's `openat` calls are still checked, but listing the delivered descriptor is not. A worker isolated another way, such as chroot, namespaces, or seccomp, is more exposed. Code that uses `Gate` without a broker has the narrower problem that `open` gave a directory descriptor to a caller holding only `READ`.

The flaw was corrected in 0.3.0: `Gate::open` checks the opened descriptor and fails with `EISDIR` if it is a directory, so the broker delivers nothing. Code that used `open` to get a directory descriptor must use `read_dir`, which needs `LIST`.
