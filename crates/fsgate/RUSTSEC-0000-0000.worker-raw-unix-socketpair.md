# `fsgate-broker`: a confined worker can send Unix datagrams outside its confinement before Linux 7.1

Before Linux 7.1, where Landlock cannot refuse Unix socket connects, `fsgate-broker` 0.4.0 installs a seccomp filter that is meant to stop its confined worker, and every program it starts, from opening a Unix socket. The filter refused `socketpair(AF_UNIX, SOCK_DGRAM, ...)` but not `SOCK_RAW`, and the kernel makes a Unix `SOCK_RAW` socket a datagram one. A confined worker could make such a pair and send datagrams, and descriptors with them, to any Unix datagram socket it could name, such as `/dev/log` or systemd-journald's socket. Stream and seqpacket sockets, such as D-Bus, were not reachable this way.

Only the confined worker of `fsgate-broker` on Linux before 7.1 is affected. `Gate::lock()` is not affected. Releases before 0.4.0 had no filter and documented that a confined worker could reach Unix sockets before Linux 7.1.

The flaw was corrected in 0.4.1: the filter allows a Unix socket pair only for `SOCK_STREAM` and `SOCK_SEQPACKET` and refuses every other type with `EACCES`.
