# A version 3 pack header can cause a panic during streaming pack input

The pack-header decoder accepted pack versions 2 and 3, but `BytesToEntriesIter::new_from_header()` immediately asserted that the decoded version was 2. A remote peer or another untrusted pack source could provide a version 3 header and trigger this assertion in release builds.

The panic interrupts streaming pack ingestion, including clone/fetch paths. It can terminate a command or the affected application thread, depending on panic handling. This is an availability issue; the header does not establish memory corruption, and the attack requires the victim to consume the supplied pack.

Version 0.75.0 removes the contradictory assertion and accepts version 3 using the same entry layout as version 2. Related pack-writing assertions were also removed so thin-pack repair and pack generation consistently support this version.

Reported by zx (Jace; @manus-use).
