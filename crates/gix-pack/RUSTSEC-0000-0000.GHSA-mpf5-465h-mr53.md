# Invalid thin-pack delta offsets can panic during fetch

When resolving a thin pack, gix-pack inserts locally available REF_DELTA bases and adjusts offsets of later entries. An OFS_DELTA base distance is subtracted from its pack offset with an unchecked `expect()`. A malicious pack containing a distance larger than that offset can therefore panic while the pack is being indexed.

The demonstrated fetch path requires a REF_DELTA base already present in the receiving repository, followed by the malformed OFS_DELTA entry. It does not trigger through this path on a fresh clone with no locally available base objects. The panic interrupts fetching and can terminate an application that does not catch it.

Update to gix-pack 0.75.0 or later. The fix validates delta base offsets and returns an input error for invalid distances instead of panicking.

Reported by zx (Jace), GitHub user `manus-use`.
