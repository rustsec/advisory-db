# `Clone` for `SslSession` and `PKey` can overflow Tongsuo's reference count

`Clone` for `SslSession` and `PKey` calls `SSL_SESSION_up_ref` and `EVP_PKEY_up_ref`. In Tongsuo these go through `CRYPTO_UP_REF`, which adds one to the result of an atomic fetch-and-add on an `int` with no upper limit, so at `INT_MAX` the addition is a signed integer overflow.

`std::mem::forget` is safe, so safe code can clone a session or key 2^31 - 2 times, forget the clones, and overflow on the next clone. A `#![forbid(unsafe_code)]` driver triggers this with tongsuo 0.10.62 and the Tongsuo 8.4.0 sources bundled in tongsuo-src. UndefinedBehaviorSanitizer reports the overflow in `SSL_SESSION_up_ref` and `EVP_PKEY_up_ref`, and one clone fewer gives no report.

No fixed version of this crate is available. Its maintainer recommends moving to `variant-ssl` with the `tongsuo` feature.
