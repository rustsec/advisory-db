# NULL pointer dereference in `Connection::trace_v2` (`SQLITE_TRACE_STMT`) on nested execution OOM

In `rusqlite` (`<= 0.43.0`, with the `trace` feature enabled), `Connection::trace_v2`'s `trace_callback` handled `SQLITE_TRACE_STMT` by passing the raw pointer directly to `CStr::from_ptr` without checking `is_null()`.

During nested statement execution (`db->nVdbeExec > 1`), SQLite's `sqlite3MPrintf` passes `NULL` to `xV2` on allocation failure (OOM or hitting `sqlite3_hard_heap_limit64`), causing an immediate NULL pointer dereference and process crash (`SIGSEGV` / `STATUS_ACCESS_VIOLATION`).

Maintainer `gwenn` fixed this issue (along with other `CStr::from_ptr` null checks across `rusqlite`) on `master` in PR #1972 (commit `b4ab171443`). No fixed release has been published to crates.io yet.
