# `IndexInfo::set_idx_cstr` allows constructing invalid UTF-8 `&str` in `VTabCursor::filter`

In `rusqlite` (`<= 0.43.0`, with the `vtab` feature enabled), `IndexInfo::set_idx_cstr(&mut self, idx_str: &'static CStr)` is a safe public method that stores an arbitrary NUL-terminated `&'static CStr` (not guaranteed to be valid UTF-8) into SQLite's `sqlite3_index_info.idxStr`.

When SQLite subsequently invokes the virtual table `xFilter` callback (`rust_filter`), `rusqlite` converted `idx_str` into `Option<&str>` via `std::str::from_utf8_unchecked` without validating UTF-8, allowing safe Rust callers to construct an invalid UTF-8 `&str` (Undefined Behavior).

Maintainer `gwenn` confirmed the issue and fixed it on `master` in PR #1971 (commit `44a157db85`) by changing `VTabCursor::filter` to receive `Option<&CStr>`. No fixed release has been published to crates.io yet.
