# Stack overflow from unbounded recursion in DTD content-model parsing

`xmloxide`'s DTD parser recursed without a depth bound when parsing the
parenthesised content model of an `<!ELEMENT>` declaration. A small document
whose internal DTD subset contains many nested `(` drives unbounded mutual
recursion between `DtdParser::parse_content_particle` and
`DtdParser::parse_content_spec_group`, exhausting the stack and aborting the
process.

The internal DTD subset is parsed during ordinary document parsing, so this is
reachable through the default parse entry points (for example
`Document::parse_str`) on any input that carries a `DOCTYPE`. The existing
`ParseOptions::max_depth` limit does not prevent it: it bounds element nesting,
not DTD content-model nesting. A stack overflow cannot be caught as an error,
so any process that parses attacker-controlled XML with `xmloxide` can be
crashed with a small payload.

Fixed in 0.4.4: a parenthesis-nesting depth counter is threaded through the
content-model parser, and nesting deeper than 256 levels is rejected with a
normal `ParseError`. Well-formed DTDs are unaffected.

Applications that cannot upgrade should reject or strip the `DOCTYPE` from
untrusted input before parsing.
