# Fiat–Shamir challenges limited to 64 bits in SHA-256 and BLAKE2b transcripts

In versions 0.7.0 and 0.7.1, the SHA-256 transcript (the default) and the
BLAKE2b transcript drew every GF(2^128) challenge from a set of only 2^64
elements: the upper half was built by repeatedly adding 2^63 to itself, which
is zero in characteristic 2. The Merlin transcript is not affected.

By the crate's own soundness accounting, affected proofs have roughly 36 to 45
bits of soundness, depending on the committed size, instead of the intended
~100 bits.

Version 0.8.0 fills all 128 bits of every challenge. SHA-256 and BLAKE2b proofs
produced by 0.7.x do not verify under 0.8.0. Versions 0.7.0 and 0.7.1 have been
yanked.

(Versions before 0.7.0 contain the same defect but are covered by the more
severe proof-forgery advisory for this crate.)

For details, see <https://github.com/rotkonetworks/ligerito/security/advisories/GHSA-v7cm-cf8f-9m54>.
