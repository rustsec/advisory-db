# Reserved Windows device names can redirect checkout writes

gix-worktree-state does not reject reserved Windows device names before checking out files. A repository containing a path such as `CON` or `CONOUT$` can therefore direct attacker-controlled file contents to a device instead of creating an ordinary worktree file.

Names are case-insensitive and some extensions or other suffixes preserve their device meaning. Console writes can appear to be trusted application messages and mislead a user into following attacker instructions. Other effects depend on the devices available, configuration, and permissions; direct arbitrary code execution or data exfiltration is not established by these examples.

This issue affects Windows workflows that fetch refs or materialize paths from untrusted repositories. Update to gix-worktree-state 0.11.0 or later. The fixing release validates path components and rejects reserved device names before the relevant disk access.

Reported by Eliah Kagan; remediation by Byron.
