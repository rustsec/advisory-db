# Panic on a multi-byte character in an UpdateExpression or ProjectionExpression

Affected versions of `dynoxide-rs` panic when an `UpdateExpression` or
`ProjectionExpression` contains a character that takes three or four bytes in
UTF-8, such as `€` or an emoji, outside a string. Building the syntax error's
`near:` text cut the expression in the middle of that character.

The `dynoxide` binary is built with `panic = "abort"`, so when it runs as an
HTTP server one request stops the whole process. No credentials are needed:
Dynoxide doesn't check request signatures. The server binds to 127.0.0.1 by
default, so the exposure is a server bound to another interface. Applications
that embed the crate get the panic from the same call (`Database::update_item`,
`get_item`, `query`, `scan`, `batch_get_item` or `transact_get_items`) unless
they abort on panic themselves.

The first affected release is 0.9.10. Version 3.0.0 (Dynoxide 1.3.0) steps over
whole characters and refuses one DynamoDB doesn't accept outside a string with
DynamoDB's own syntax error.
