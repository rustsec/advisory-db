# OAuth client access tokens accepted as user sessions; client scope not enforced

Access tokens issued to an OAuth client were indistinguishable from user session tokens. Endpoints that require a signed-in user accepted them, and a client's registered scope constrained only the token's scope string. A registered client could therefore act with user-session authority.

Affected: 0.4.0 to 0.4.45, 0.5.0-rc1 to 0.5.0-rc79, and 0.6.0-rc41, rc42 and rc45. All affected versions are already yanked. Versions before 0.4.0 were not examined.

## Patched
0.4.46, 0.5.0-rc82 and 0.6.0-rc46 (and later 0.6.0 releases). Tokens issued to a client are now bound to the client and refused by session endpoints, and a client is granted only its registered scopes. Session endpoints now refuse client-issued tokens and `/oauth/authorize` refuses unregistered scopes (`invalid_scope`). Tokens issued before the upgrade carry no client binding and remain accepted until they expire.

Integrators with routes meant for delegated access should use the delegated-token validation added in the fixed releases.
