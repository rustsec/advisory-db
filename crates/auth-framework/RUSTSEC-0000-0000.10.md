# TotpManager derives a predictable fallback TOTP secret, allowing MFA bypass for unenrolled users

`TotpManager::get_user_secret` (module `auth_modular::mfa::totp`), reached through the public `AuthFramework::verify_totp_code` and `fw.mfa().verify_totp`, derives and persists a fallback TOTP secret when no secret is stored for a user: `SHA256(user_id || "totp_secret_salt_2024")[..20]`. The value uses no server-side secret and no random input, so it is a pure function of the user id.

Anyone who knows or can guess a user id can compute the same secret offline, generate valid TOTP codes and pass MFA verification for that user without ever seeing a real enrollment secret. This affects any user who has not enrolled TOTP through the modular path, including every user who enrolled via the REST routes `/mfa/setup` and `/mfa/verify`, because that route pair never reads the `TotpManager` storage key.

Affected: 0.4.0 to 0.4.4 and 0.5.0-rc1 to 0.5.0-rc25 (by the GHSA range). Fixed in 0.4.5 and 0.5.0-rc26: the derived fallback is removed, so a user with no enrolled secret fails verification. No workaround short of a code change is known.
