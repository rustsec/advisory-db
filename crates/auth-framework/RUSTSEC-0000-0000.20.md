# Third-party caveats in `protocols::macaroons` were not verified

`MacaroonManager::verify_with_discharges` accepted a discharge macaroon for a third-party caveat when its identifier matched the caveat's identifier. The discharge's signature was computed and then discarded, and the discharge's own caveats were never checked. Anyone holding a macaroon that carries a third-party caveat could build a discharge with the matching identifier and any signature, and verification succeeded without the third party's approval.

Only applications that attach third-party caveats with this module and verify them with `verify_with_discharges` are affected. The crate does not call this API itself. First-party caveats and the HMAC chain over the caveats were not affected.

The fixed versions (0.5.0-rc65, 0.6.0-rc150) remove the third-party caveat and discharge API, so code that calls it no longer compiles, and a serialized macaroon that carries a third-party caveat is refused when it is parsed. Upgrade to a fixed release and move any third-party check into your own verifier.
