# Default configuration signed tokens with a published, fixed secret

`AppConfig::default()` (and the configuration builder when no JWT secret was set) used a fixed, publicly readable JWT signing secret. A deployment built from the default configuration, or from the builder without setting its own secret, signed tokens with that known key, so anyone could forge tokens that the deployment accepts. Production-mode validation did not reject the value (`AuthFramework::new_validated` returned Ok with it).

Present in every published version from 0.4.0 up to 0.4.27, 0.5.0-rc1 up to 0.5.0-rc48 and 0.6.0-rc41 up to 0.6.0-rc72.

Fixed in 0.4.28, 0.5.0-rc49 and 0.6.0-rc73: the default configuration now generates a random per-process secret. Those three versions have since been yanked because they still contained other fixed keys (see GHSA-jr9j-g3xj-q9x8); use 0.4.29, 0.5.0-rc51 or 0.6.0-rc85 or newer.

Deployments that relied on the default must configure their own secret, and any token signed with the old constant should be treated as forgeable: rotate your secret and invalidate outstanding tokens.
