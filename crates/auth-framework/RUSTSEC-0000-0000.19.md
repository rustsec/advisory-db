# Shared Signals `receive_event` accepted unsigned or dev-key-signed security events

`SharedSignalsManager::receive_event` (module `server::oidc::oidc_extensions`) accepted security events without a valid signature while event verification was enabled. An event carrying no signed token was accepted, and when `SHARED_SIGNALS_VERIFICATION_KEY` was unset a token signed with a fixed constant in the published source verified.

A caller that exposes `receive_event` to untrusted senders could be made to revoke sessions, disable accounts or record credential changes. The crate does not itself route network requests to this method, so only applications that pass untrusted events to it are affected.

The fixed versions (0.4.42, 0.5.0-rc63, 0.6.0-rc138) require a configured key and a signed token; unsigned events now return an error. This is a behaviour change for callers that fed unsigned events.

Upgrade to the newest release of your line. Treat any session revocation, account change or credential-change record that arrived through `receive_event` before the upgrade as unverified.
