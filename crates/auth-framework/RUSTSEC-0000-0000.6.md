# Step-up MFA accepts an incorrect code in MfaManager::complete_cross_method_step

`MfaManager::complete_cross_method_step` treats every non-error verifier result as success. The TOTP, SMS, email and backup-code verifiers return `Ok(false)` for an incorrect or malformed code, so any code completes a step-up MFA step and the method is marked completed. This bypasses step-up MFA in applications that use the step-up API (`initiate_step_up_authentication` / `complete_cross_method_step`). The bundled HTTP server does not call this API.

Affected: 0.4.0 to 0.4.2 and 0.5.0-rc1 to 0.5.0-rc24 (by the GHSA range). Fixed in 0.4.3 and 0.5.0-rc25: success now requires `Ok(true)`. Workaround: do not use `complete_cross_method_step`; verify codes with the method's verifier directly and treat only `Ok(true)` as success.

Upgrade note: on 0.4.x, secrets from `TotpManager::generate_secret` are not base32, so after upgrading to 0.4.3 step-up TOTP correctly fails for those users and they must re-enroll.
