# MFA completion has no attempt limit and trusts caller-supplied challenge data

Two defects in second-factor completion.

1. **HTTP login with MFA** (`/auth/login` with challenge id plus code, feature `api-server`): nothing counted failed second-factor attempts and the per-username lockout did not apply to the MFA branch, so six-digit codes could be brute-forced against a victim whose password is known. Affects 0.5.0-rc18 up to 0.6.0-rc45 (no MFA login branch in 0.4.x and earlier).
2. **Library `complete_mfa`**: the code was verified against the stored challenge, but the token was minted for the `user_id` of the challenge value supplied by the caller. The shipped HTTP server always passes the stored challenge, so it cannot be driven from the API; only applications that call `complete_mfa` with a challenge value built from client input were exposed (sign-in as an arbitrary user id by anyone holding a real challenge id and a valid code for any account). Affects every published version from 0.1.1 up to 0.6.0-rc45.

The only patched version is 0.6.0-rc46; there is no patched release on 0.1.x to 0.5.x. Applications must never pass client-built challenge values to `complete_mfa`; on 0.5.0-rc31 and 0.6.x use `complete_mfa_by_id`. The fix also adds attempt limits (account lockout `ACCOUNT_LOCKED` after 5 wrong codes per 15 minutes).
