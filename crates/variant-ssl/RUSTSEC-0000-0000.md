# Catching a clone panic after reference-count overflow can leave dangling handles

`Clone` for types such as `PKey`, `SslSession` and `X509` calls the matching OpenSSL `*_up_ref` function. These functions increment the reference count before they report failure, so a failed call means the count has already overflowed. Earlier versions panicked on that failure. With variant-ssl 0.18.2 and OpenSSL 4.1.0, UndefinedBehaviorSanitizer reports the overflow for all three types, and the panic can be caught with `std::panic::catch_unwind`. Pull request 2713 describes how cloning can then continue, forgetting each clone, until the wrapped count is small and positive again, so that dropping a handle frees the object while other handles still use it. The BoringSSL and AWS-LC backends saturate the count instead.

Version 0.18.4 includes rust-openssl pull request 2713, which aborts the process when an `*_up_ref` call fails, as `Arc` does. The overflow of the counter itself happens inside OpenSSL and is not changed by this fix.
