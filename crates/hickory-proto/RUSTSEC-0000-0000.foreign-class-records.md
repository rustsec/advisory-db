# Records with a DNS class other than the query's marked secure without being validated (hickory-proto)

Before 0.26.0-beta.1, hickory-proto's DNSSEC validation ignored the DNS class when grouping records into RRsets and left records of a class other than IN out of signature checking, then marked them secure if the IN records validated. Someone who can answer or modify DNS responses could add forged records of another class, including a DS record, and have them returned as validated.

From 0.26.0-beta.1 the DNSSEC validation code lives in the hickory-net crate, where this was fixed in hickory-net 0.26.2. No hickory-proto release contains a fix. Users of DNSSEC validation in older hickory-proto releases (directly or through hickory-resolver or hickory-recursor) should move to the 0.26.2 or later releases, which validate through hickory-net.
