# `_string` and `_pathbuf` called `CStr::from_ptr` on an unchecked pointer

Before 0.18.0, safe `_string` and `_pathbuf` passed a `*const c_char` straight to `CStr::from_ptr` and returned an owned string. A null pointer is undefined behavior.

0.18.0, published 2025-03-28, returns `Option` and checks `is_null` before `from_ptr`. That is the first release after the 2024-11-27 report. 0.17.1, the release current at the time of the report, still had the unchecked call. The same null check is in 0.19.0.
