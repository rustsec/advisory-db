# `Clone` for `PKey`, `SslSession` and `X509` can overflow OpenSSL's reference count

`Clone` for `PKey`, `SslSession` and `X509` calls the matching OpenSSL `*_up_ref` function, which increments the reference count before it reports failure. `std::mem::forget` is safe, so safe code can clone one of these values 2^31 - 2 times, forget the clones, and drive the count to `INT_MAX`; the next clone then performs a signed integer overflow inside OpenSSL. A driver with no `unsafe` code triggers this with OpenSSL 4.1.0 for `PKey` and `X509` on openssl 0.10.81 and 0.10.82, and UndefinedBehaviorSanitizer reports the overflow at the increment. For `SslSession`, we verified the call path in the `openssl` source.

Version 0.10.81 ignores the return value of the `*_up_ref` call, and version 0.10.82 panics when the call fails. As described in pull request 2713, a caller can catch that panic and keep cloning until the wrapped count is small and positive again, after which dropping a handle frees the object while other handles still use it. The pull request, merged on 2026-11-05, makes the process abort when an `*_up_ref` call fails; no release contains it yet. The overflow of the counter itself happens inside OpenSSL and is not changed by this fix.
