# `Clone` on cvc5 handles can wrap the C API reference count and free a live object

The cvc5 C API keeps a 32-bit reference count on terms, sorts and the other objects listed below, and increments it in the `*_copy` functions with no bound check. In cvc5-rs, `Clone` for `Term` calls `cvc5_term_copy` and `Drop` calls `cvc5_term_release`; the other handle types (sorts, operators, datatypes and their declarations, constructors and selectors, grammars, results, synthesis results and proofs) follow the same pattern with their own `*_copy` and `*_release` functions.

`std::mem::forget` is safe, so safe code can clone a handle and forget the clones until the 32-bit count wraps around to one while two handles are still live. Dropping one of them then frees the object, and the next call through the other reads freed memory.

A `#![forbid(unsafe_code)]` driver triggers this with cvc5-rs 0.3.2 and cvc5 1.3.1. AddressSanitizer reports a heap use-after-free on the next use of the surviving handle, and one fewer forgotten clone gives no report. The successor crate, `cvc5`, still uses the C copy function for `Term::clone` in 0.6.1.

No fixed version is available.
