# Malformed commit-graph files can cause panics during history traversal

The commit-graph reader used attacker-controlled parent positions without checking them against the graph's commit count. It also accepted an extended-edge (`EDGE`) chunk whose length was not a multiple of its four-byte record size. Traversing these values could panic through an out-of-range graph lookup or a short record conversion.

Applications and commands that open an attacker-controlled local repository or repository archive and use its commit-graph for history traversal are exposed. A panic can terminate the affected command or calling thread; whether an embedding application loses its entire process depends on its panic strategy and handling. Commit-graph files are local repository metadata and are not transferred by the normal Git clone/fetch object protocol.

`gix-commitgraph` 0.42.0 checks parent positions during ordinary traversal and rejects malformed edge lengths and offsets. `gitoxide` 0.61.0 incorporates this fix. Avoid processing untrusted commit-graph metadata with affected versions.
