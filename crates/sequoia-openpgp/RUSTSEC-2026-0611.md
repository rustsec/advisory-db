# Tolerant ASCII armor parsing can select a different block than a strict parser

The ASCII armor parser has a new mode, `ReaderMode::Strict`, which only
considers compliant ASCII-armor blocks.  This should be used when it is
essential that a message be understood in the same way by different
implementations.  For instance, an attacker could leverage the current tolerant
mode to create a message that is interpreted one way by Sequoia and another way
by a different implementation.  Imagine a file that contains an out-of-spec
ASCII-armor block that only Sequoia understands followed by a fully valid
ASCII-armor block.  Sequoia will parse the first block and the other
implementation will parse the second one. This can lead to two people who have
the message assuming that the same thing has been parsed, when in fact they got
different things.

To prevent this attack, users must explicitly select `ReaderMode::Strict`.
