# `Clone` on cvc5 handles can wrap the C API reference count and free a live object

The cvc5 C API keeps a 32-bit reference count on terms and increments it in the `*_copy` functions with no bound check. In this crate, `Clone` for `Term` calls `term_copy` (the C API's `cvc5_term_copy`) and `Drop` releases the reference.

`std::mem::forget` is safe, so safe code can clone a handle and forget the clones until the 32-bit count wraps around to one while two handles are still live. Dropping one of them then frees the object, and the next call through the other reads freed memory.

A `#![forbid(unsafe_code)]` driver triggers the same use-after-free with the crate's earlier release under the name `cvc5-rs` (0.3.2, with cvc5 1.3.1), and AddressSanitizer reports it. Source inspection shows the same `Term` copy and release calls in `cvc5` 0.6.1 and the unchecked increment in cvc5 1.4.2. The reproducer was not run on 0.6.1.

No fixed version is available.
