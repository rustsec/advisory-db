# `AffinePlan::run` passes dangling host pointers to the strided CUDA launcher

`AffinePlan::run` is a safe function. When its input or output tensor is not
contiguous, it takes the strided path, which called `.as_ptr()` on the arrays
returned by `TensorRef::shape()`, `TensorRef::stride()` and `TensorMut::stride()`.
Those accessors return the arrays **by value**, so each pointer referred to a
temporary that was dropped at the end of its statement. The pointers were then
passed to `baracuda_kernels_affine_<dtype>_strided_run`, whose host launcher
(`launch_affine_strided`) reads `shape[d]`, `stride_x[d]` and `stride_y[d]` from
them before launching the kernel. That is a read of a dead stack object
(undefined behavior); the values fed to the kernel's index arithmetic may be
arbitrary, which could make the kernel read or write out of bounds on the
device. No such out-of-bounds access was demonstrated: in practice the dead
stack slot is usually still intact, and the crate's own strided on-device tests
passed on the affected versions.

The defect was introduced in `0.0.1-alpha.138`, when the tensor fields were made
private behind by-value accessors; `0.0.1-alpha.137` read the fields directly and
is not affected. The rustc lint `dangling_pointers_from_temporaries` flags all
affected sites.

The same pattern existed for the mask strides in the strided path of
`SdpaPlan::run`; the strided SDPA launcher currently ignores that argument, so
it was latent there.

The flaw was fixed in `0.0.1-alpha.158` by binding the arrays to locals so the
pointers outlive the call.

Published affected versions (crates.io index): `0.0.1-alpha.138`, `.139`, `.140`
and `.147`.
