# Cross-origin challenge/token replay in Key Vault authentication policy

Affected versions can reuse cached challenge authentication state across requests that
do not preserve the original trusted vault origin. This can cause authorization data
to be attached to a different destination than the one that established the challenge.

For `azure_security_keyvault_certificates`, the affected ranges include stable
`0.9.0` through `1.0.0` and preview `1.1.0-beta.1`.

## Impact

Applications can send authentication material to an unintended Key Vault endpoint when
request flows cross origin boundaries.

## Fix

Update to `1.0.1` (stable) or `1.1.0-beta.2` (preview), which enforce strict
origin-scoped challenge handling.
