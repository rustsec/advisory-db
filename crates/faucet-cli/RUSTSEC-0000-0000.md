# Path-root bypass for file reads and writes in faucet serve

**Summary.** A relative path shaped like a URL with an unknown scheme (`zz:/../..`) was classified as a remote URL, so it skipped the server's path-root confinement. The file connectors then opened it as a local path. A submitter could read or write any file the server's user can access, through file sources and sinks, previews, and DLQ inspect/discard/replay. Related shapes were affected too: percent-encoded `sqlite:` URLs (`%2F`, `%2e%2e`) and SQL-transform relation paths starting with `~`.

**Fix.** Only `scheme://` values whose scheme the connector actually opens remotely are treated as URLs; every other value is a local path, canonicalised and checked against the roots. These are refused:
- a relative first segment containing `:` (drive letters excepted);
- a leading `~`;
- `..` inside a URL.

`sqlite:` and `duckdb:` names are decoded the way their drivers decode them before the check.

**Workaround.** None short of upgrading; restrict the `operator` role.

**Affected:** `faucet-cli` <= 1.16.0, including the prebuilt binaries and container images of those versions. **Patched:** 1.17.0.

This applies only to `faucet serve`: configs submitted to a running server through the HTTP API, MCP, triggers or templates. One-shot `faucet run` and `faucet schedule` runs of the operator's own configs are not affected.
