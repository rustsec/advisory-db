# faucet serve sends its PostgreSQL environment credentials to a submitter-chosen host

**Summary.** When a submitted PostgreSQL connection URL named no password or user, the PostgreSQL connectors (source, sink, CDC, state store, Redshift) filled them from the server's environment (`PGPASSWORD`, `PGUSER`, `~/.pgpass`, `PGSSLKEY`…). A submitter could point a connection at a server they control and receive the server's database password, in cleartext if that server requested it.

**Fix.** Under `faucet serve`, PostgreSQL connections use only the settings in their config. A URL that leaves out a user, client certificate, root certificate or `options` while the matching `PG*` variable is set is refused. One-shot `faucet run` behaves as before.

**Workaround.** Don't set `PG*` credential variables or keep a `.pgpass` in the `faucet serve` process's environment.

**Affected:** `faucet-cli` <= 1.16.0, including the prebuilt binaries and container images of those versions. **Patched:** 1.17.0.

This applies only to `faucet serve`: configs submitted to a running server through the HTTP API, MCP, triggers or templates. One-shot `faucet run` and `faucet schedule` runs of the operator's own configs are not affected.
