# faucet serve's environment file readable as pipeline data

**Summary.** `faucet serve` loads `.env` from its working directory, and the working directory is a default path root. A submitter could read `.env` (and other server input files) as data through a file source or preview. That exposed the server's own tokens, including `--auth-token`, RBAC tokens, `FAUCET_VAULT_KEY` and credentials, allowing escalation from `operator` to `admin`.

**Fix.** The server's own files are refused as data whatever the path roots allow:
- every `.env` / `.env.*` in its working directory, and the env file it loaded;
- the files given by `--auth-config`, `--policy`, `--triggers`, `--templates-sync`, `--connect-providers`, `--default-config` and `--otel-config`;
- the history database;
- the default config's state directory.

**Workaround.** Run `faucet serve` with `--no-env-file` and pass secrets through the process environment, or start it from a directory that holds no secrets.

**Affected:** `faucet-cli` <= 1.16.0, including the prebuilt binaries and container images of those versions. **Patched:** 1.17.0.

This applies only to `faucet serve`: configs submitted to a running server through the HTTP API, MCP, triggers or templates. One-shot `faucet run` and `faucet schedule` runs of the operator's own configs are not affected.
