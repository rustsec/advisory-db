# Asynchronous host copies were safe functions: use-after-free and data race on host buffers

`DeviceBuffer::copy_from_host_async`, `DeviceBuffer::copy_to_host_async` and `memcpy2d::copy_h_to_d_2d_async` enqueue a copy on a CUDA stream and return. They borrowed the host slice only for the duration of the call, but with page-locked memory (`PinnedHostBuffer`, `PinnedRegistration`, both public and `Deref` to a slice) the DMA runs after the call returns. Safe code could drop, move or write (or, for device-to-host, read) the host buffer while the copy was still in flight: a use-after-free or data race that the borrow checker could not see.

Affected: every published version from 0.0.1-alpha.2 through 0.0.1-alpha.126. Fixed in 0.0.1-alpha.137 (alpha.127 to alpha.136 were never published): these functions are now `unsafe fn` with a `# Safety` contract (the host memory must stay valid and untouched until the stream is synchronized or an event recorded after the copy completes). This is a breaking change: call sites need an `unsafe` block.

Separately, versions before 0.0.1-alpha.137 also use a `baracuda-cuda-sys` whose struct layouts were too small (see the `baracuda-cuda-sys` advisory), which `query::pointer_attributes` and `array::TextureObject::new` expose as an out-of-bounds write and read.

Impact: memory corruption (the device writes into freed or reused host memory) or exposure (stale or freed host memory is copied to the device) from safe code that drops or mutates a pinned buffer before synchronizing. Action: upgrade to 0.0.1-alpha.137 or later and keep host memory alive until the stream is synchronized. Workaround before upgrading: synchronize the stream before any drop, move, write or read of the host buffer.
