# `undelegate` accepts a buffer that is not the account's undelegation buffer PDA

`instruction::undelegate` re-creates a delegated account during the
undelegation callback and copies the committed state from the delegation
program's buffer into it.

Before 0.16.2 the only check on `buffer` was that it signed the
instruction. Its owner was not checked, and it was not checked to be the
`undelegate-buffer` PDA derived from `delegated_account`. A buffer that
belongs to another account could be passed in and its data would be written
into `delegated_account`.

This is the same missing check that was fixed in `ephemeral-rollups-sdk`
0.16.2. In 0.16.2 `undelegate` also requires the buffer to be owned by the
delegation program and to equal the canonical undelegation buffer PDA.
Programs built against an earlier version need to be rebuilt with 0.16.2 or
later and redeployed.
