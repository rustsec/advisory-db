# Subscriber API does not include bound and size/alignment checks

## Summary

`SampleReceiver::<T>::take()` and `Sample::<T>::deref()` are safe functions that hand the caller a `&T` pointing at a chunk written by another iceoryx process, but the subscriber path neither requires `T`: ShmSend nor verifies that the received chunk is at least `size_of::<T>()` bytes / `align_of::<T>()-aligned`. A peer process that publishes an undersized chunk, or any chunk at all when the subscriber chose a pointer-bearing `T`, drives a `#![forbid(unsafe_code)]` subscriber into out-of-bounds reads of adjacent shared-memory chunks or dereference of a publisher-controlled pointer.

## Resolution

It will not be fixed in iceoryx-rs since this is a known limitation in classic [iceoryx](https://github.com/eclipse-iceoryx/iceoryx) as it is the users responsibility to specify the same data type on sender and receiver side.

[iceoryx2](https://github.com/eclipse-iceoryx/iceoryx2) is the successor of iceoryx-rs where the API there is designed to prevent this by default.
It is strongly recommended to migrate to iceoryx2 which is actively maintained and receives security support.
The iceoryx-rs package has officially reached End-of-life and will not receive any features, bugfixes or security fixes.
