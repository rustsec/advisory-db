# Bundled Brotli C decoder vulnerable to out-of-bounds write (CVE-2026-111497)

The `brotlic-sys` crate provides Rust bindings to Google's Brotli compression library and bundles the underlying C implementation.

Version 0.2.2 includes a vulnerable version of the Brotli decoder affected by CVE-2026-111497, an out-of-bounds write vulnerability in the block-type switch handling logic within `c/dec/decode.c`.

Static analysis of the packaged source confirms that the vulnerable `DecodeBlockTypeAndLength()` implementation is present and does not contain the upstream security fix.

Specifically:

- `DecodeBlockTypeAndLength()` returns `BROTLI_BOOL` rather than `BrotliDecoderErrorCode`.
- Invalid block-type conditions return `BROTLI_FALSE` without propagating a specific decoder format error.
- The `DecodeCommandBlockSwitch()` fast path invokes `DecodeCommandBlockSwitchInternal()` without checking its return value.
- The patched upstream error-handling implementation is absent.

Applications using `brotlic-sys` to decompress attacker-controlled Brotli streams may be exposed to memory corruption, denial of service, and potentially arbitrary code execution.

The vulnerability also affects downstream Rust crates that consume the bundled decoder, including `brotlic` when resolved to the vulnerable `brotlic-sys` release.

## Source-level evidence

Inspection of the `brotlic-sys` 0.2.2 source archive shows the
pre-fix implementation of `DecodeBlockTypeAndLength` in
`brotli/c/dec/decode.c`:

```c
static BROTLI_INLINE BROTLI_BOOL DecodeBlockTypeAndLength(
    int safe, BrotliDecoderState* s, int tree_type) {
  uint32_t max_block_type = s->num_block_types[tree_type];
  /* ... */
  if (max_block_type <= 1) {
    return BROTLI_FALSE;
  }
  /* ... */
}
```

The decoder's fast command block-switch wrapper discards the result:

```c
static void BROTLI_NOINLINE DecodeCommandBlockSwitch(
    BrotliDecoderState* s) {
  DecodeCommandBlockSwitchInternal(0, s);
}
```

The upstream remediation changes block-switch error propagation so invalid
conditions can be reported and handled rather than ignored. These source
signatures demonstrate that the bundled decoder lacks that remediation.

## Impact

Applications using the affected `brotlic` decoding APIs to decompress
untrusted Brotli streams may expose the memory-corruption vulnerability.
The presence of the vulnerable source code does **not** establish that
remote exploitation is possible in every consumer of the crate. No
crate-specific exploit has been demonstrated as part of this report.

## Remediation

Users should move to a `brotlic-sys` release that includes the upstream
Brotli decoder fixes, once one is available, and rebuild applications
using `brotlic`. If no corrected crate is available, avoid decompressing
untrusted Brotli data using this decoder or use an alternative verified
unaffected implementation.

**Version-scope note:** The published `brotlic` 0.8.2 release and its
`brotlic-sys` 0.2.2 resolution were examined. Earlier releases and other
possible compatible dependency resolutions were not exhaustively audited.
`patched = []` indicates that no fixed `brotlic` release was identified at
the time of drafting; it should not be interpreted as proof that every
historical release has been audited.
