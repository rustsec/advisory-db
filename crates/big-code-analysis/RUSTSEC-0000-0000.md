# Stack overflow computing `npa` on deep Python assignment chains and Elixir `defstruct` lists

Computing the `npa` metric (number of public attributes) recursed once
per link of a Python class-level chained assignment (`a = a = … = 1`)
and once per bracket of a nested Elixir `defstruct` list. A crafted
source file with a chain a few thousand links long, or a list nested
about ten thousand brackets deep, overflows the stack of the thread
running the analysis and aborts the process; a stack overflow is not a
catchable panic.

Every interface that computes `npa` is affected, including `analyze` and
`Ast::metrics` with `npa` selected, and the `bca` and `bca-web` binaries
built on this crate. The Elixir path is affected from 1.0.0 and the
Python path from 2.0.0.

Fixed in 2.6.0: the Python reader steps along the chain in a loop and
the Elixir count keeps its own stack.
