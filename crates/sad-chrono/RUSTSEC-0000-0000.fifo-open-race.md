# Time zone file loading can block indefinitely on a FIFO (fixed on listed Unix targets)

To determine the local time zone, `Local` opens a TZif file selected by the `TZ` environment
variable, `/etc/localtime`, or the system zoneinfo directories, and on Android and OpenHarmony a
`tzdata` bundle. A blocking open of a FIFO waits for a writer, so a FIFO at one of these paths could
block `Local::now()` and other `Local` operations indefinitely.

- In 0.4.46, 0.4.47, and 0.5.0, TZif paths were checked to be regular files before opening and
  checked again on the opened handle. Because the open itself could block, a concurrent change to a
  selected path between the check and the open could still block the opening thread.
- Android and OpenHarmony `tzdata` paths had no regular-file check in 0.4.46 or 0.5.0, so a FIFO at
  such a path blocked without any race. 0.4.47 added pre-open and handle checks to those paths, with
  the same race as above.

0.4.48 and 0.5.1 open these files with `O_NONBLOCK` and verify on the opened handle that the file is
regular. This prevents FIFO-open hangs on Linux (including OpenHarmony) and Android on `x86`,
`x86_64`, `arm`, `aarch64`, `riscv32`, `riscv64`, `s390x`, `powerpc`, `powerpc64`, and
`loongarch64`; on Apple platforms, FreeBSD, DragonFly, NetBSD, and OpenBSD; and on Solaris and
illumos. **On other Unix targets, these files are still opened without `O_NONBLOCK`, so a concurrent
path replacement can still block the calling thread after upgrading. On those targets, use trusted
time zone paths and directories.** Files read by the `iana-time-zone` dependency during `Local`'s
fallback lookup are outside this fix.

Exposure requires the ability to set the process's `TZ` (or, on Android, `ANDROID_*`) environment
variables, or to create or replace files at the time zone paths it reads.
