# `rkyv` validation accepted out-of-range date and time values in 0.4.46

In 0.4.46, with `rkyv-validation` and one of `rkyv`, `rkyv-16`, `rkyv-32`, or `rkyv-64` enabled,
archive validation with `rkyv::check_archived_root` and checked deserialization with
`rkyv::from_bytes` could accept `NaiveDate`,
`NaiveTime`, `TimeDelta`, `FixedOffset`, or `IsoWeek` values outside their documented ranges or with
inconsistent fields. The derived `CheckBytes` implementations validated the archived layout but not
these types' semantic constraints. Subsequent use of such values could panic or return incorrect
results.

0.4.47 implements `CheckBytes` for these types with invariant checks, so such archives fail
validation. The 0.5 line uses `rkyv` 0.8 and has enforced these constraints through
`bytecheck::Verify` since 0.5.0.

The 0.4 line still depends on `rkyv` 0.7. RUSTSEC-2026-0235 separately covers shared-pointer
validation in `rkyv` itself. The 0.5 line requires `rkyv` 0.8.18 or a later compatible release.
