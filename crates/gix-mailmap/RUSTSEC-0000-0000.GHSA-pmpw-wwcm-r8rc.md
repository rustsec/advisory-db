# Quadratic mailmap construction can cause excessive CPU consumption

Constructing a mailmap snapshot inserted each mapping into a vector kept in sorted order. Reverse-ordered email keys, or reverse-ordered name keys for the same email, repeatedly shifted the existing entries, making construction quadratic in the number of mappings.

A repository author can supply a small `.mailmap` that causes lengthy CPU consumption when an application resolves identities through `Snapshot::from_bytes()`. The same insertion behavior affected `Snapshot::new()` and batched `Snapshot::merge()`. Repository analysis services can lose worker time; interactive commands can appear to hang. The reported issue concerns excessive CPU use rather than memory corruption.

Version 0.35.0 collects mappings and performs stable sorting and consolidation in bulk, preserving lookup and mapping precedence. Applications unable to upgrade should limit the size of untrusted mailmaps or avoid resolving them.

Reported by @NotAFlightRisk.
