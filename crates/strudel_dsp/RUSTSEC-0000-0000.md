# Unsoundness in SlabBox when performing mem::swap or storing beyond SlabBox

## Summary

The public APIs of SlabBox (including SlabBox::component, SlabBox::component_mut, and automatic dereference/borrowing traits such as DerefMut, AsMut, BorrowMut) exposed unbranded
references to internal arena-backed components. Because Rust cannot prevent safe types from being moved or swapped via mem::swap, mem::replace, or mem::take, or prevent internal
components from escaping their container (such as via thread_local!), these methods allowed references to outlive or cross-contaminate their parent SlabBox arenas.

## Impact

Memory corruption resulting in a Use-After-Free (UAF) vulnerability under specific usage patterns:

- Cross-Box Swapping: If a user performs a mem::swap between two SlabBox
  instances (directly or via component_mut), the memory regions of one box point into the arena of the other. When the first box is dropped, the second box retains dangling
  pointers into freed memory.
- Reference Escaping: If a user stores an internal component or region reference (e.g., inside a thread_local!) and the underlying SlabBox is subsequently
  deallocated, accessing the stored reference later triggers a use-after-free.

## Patch

Fixed in 0.2.0 using a unique branded lifetime.
