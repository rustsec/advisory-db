# Legacy Shrink, Reduce and Implode decoders preallocate the declared uncompressed size

With the `legacy-zip` feature, the decoders for the Shrink, Reduce and Implode compression methods reserved output capacity for the entry's declared uncompressed size before decoding anything. That size comes from the archive, and a ZIP64 entry can declare any 64-bit value, so reading or extracting a crafted entry of a few bytes panics with "capacity overflow" or fails a huge allocation.

An attacker who can supply an archive can stop a process that reads it, for example through `ZipArchive::extract`.

Only builds with the `legacy-zip` feature are affected; it is not enabled by default.

The fix caps the preallocation at 1 MiB, and such an entry now returns an error.
