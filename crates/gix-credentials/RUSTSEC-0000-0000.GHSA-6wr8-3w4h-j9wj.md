# Carriage returns can inject fields into credential-helper requests

gix-credentials writes URL context values into the external credential-helper line protocol after rejecting NUL and LF, but does not reject a bare carriage return. Helpers that treat CR as a line separator can therefore interpret an attacker-controlled URL value as additional fields, such as a trusted host name.

The attack requires an application to request credentials for an attacker-controlled URL, a configured CR-sensitive helper, and stored credentials for the injected host. It can cause credentials for that host to be returned to the caller handling the attacker URL. Disclosure to the attacker depends on how the surrounding application subsequently uses or exposes those credentials; helpers that split only on LF were not demonstrated affected.

Update to gix-credentials 0.38.2 or later. The fix rejects carriage returns in keys and values before writing requests to helpers.

Reported by Team Atlanta and GitHub user `hibrian827`.
