# HTTP server transport shuts down when a client disconnects before its response is ready

The Streamable HTTP server transport treated a response it could not deliver as fatal. When a client closed its connection before its request was answered -- a client timeout shorter than a slow handler, a proxy idle timeout, or a deliberate disconnect -- the late response could not reach the dropped request, and the transport cancelled itself: `App::run` returned and the server stopped accepting requests.

A single request was enough, from any client able to reach the endpoint, or from any authenticated client when authentication is configured. Servers using the stdio transport are not affected.

The flaw was corrected in 0.6.2 (commit cf0eca8): a response whose caller has gone away is now dropped, and a request that goes away releases its slot for the response.
