# Client-supplied tenant id reached a filesystem path (path traversal creates directories outside the data directory)

`CreateService` (handled in `server::ws_handler`) built `tenant_{tenant_id}` from the session's tenant id, which was the client's own string, and called `create_dir_all` on it. A tenant id such as `a/../../x` resolved to a directory outside the working/data directory (the component `tenant_a` is an ordinary directory, then `..` climbs out; backslashes behave the same on Windows). Combined with the unauthenticated administrator access in the same releases (see GHSA-5q28-5hrh-w432), this allowed unauthenticated directory creation at attacker-chosen locations.

Affected: 0.2.2 to 0.3.1 (first introduced in 0.2.2; 0.2.0 and 0.2.1 build no tenant paths). Fixed in 0.4.1: tenant ids are a validated type (`TenantId`: 1 to 64 characters of `A-Za-z0-9_-`, no separators or dots), parsed at the wire boundary so an invalid id cannot reach a path.

Impact: directory creation outside the data directory (and, depending on later file operations, writes there). Workaround: do not expose the server to untrusted clients; upgrade to 0.4.1.
