# Zero-size layout passed to `alloc` and `dealloc` for a zero-sized element type

`Caja::new_uninitialized(n)` passes `Layout::array::<T>(n)` to
`std::alloc::alloc`, and `Drop` passes the same layout to `dealloc`. For a
zero-sized `T` this layout has size 0 for every `n`, and calling `alloc` with
a zero-size layout is undefined behavior. The safe constructors
`Caja::new(n, x)`, `Caja::from(&[x; n])` and `clone()` all go through it.

For example, with `#[derive(Clone, Copy)] struct Zst;`, the call
`Caja::new(4, Zst)` passes a zero-size layout to `alloc`. A normal run happens
to succeed because the system allocator accepts the call, but Miri reports it
as undefined behavior ("creating allocation with size 0") at `src/lib.rs:58`.

This can be triggered through safe public APIs — `Caja::new()`, `Caja::from()`
or `clone()` with a zero-sized element type — with no `unsafe` required from
the caller.
