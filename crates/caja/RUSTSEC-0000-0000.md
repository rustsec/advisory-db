# `Caja::as_mut_slice()` returns aliasing `&mut [T]` from `&self`

`Caja::as_mut_slice()` takes `&self` but returns `&mut [T]` over the whole
array. Any number of shared borrows of a `Caja` can exist at once, so calling
`as_mut_slice()` twice gives two live mutable slices of the same elements.
This breaks Rust's aliasing rules and is undefined behavior.

For example, with `let caja = Caja::<u8>::new(1, 0)`, the calls
`let a = caja.as_mut_slice(); let b = caja.as_mut_slice();` both compile.
After `a[0] = 1; b[0] = 2;`, reading `a[0]` gives 2, a value never written
through `a`. Miri reports the write through `a` as undefined behavior, since
the second `as_mut_slice()` call invalidated `a`'s borrow.

This can be triggered through safe public APIs — `Caja::new()` and two calls to
`as_mut_slice()` on the same value — with no `unsafe` required from the caller.
