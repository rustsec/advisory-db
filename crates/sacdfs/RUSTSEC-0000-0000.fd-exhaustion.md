# File descriptor exhaustion through unbounded sidecar opens

Each open of a sidecar file (such as `cover.jpg`) held a file descriptor in the daemon with no cap, so a local user of the mount, or a guest on a network share of it, could use up the daemon's descriptors.
Images that then failed to open were left out of directory listings, and the listings stayed wrong after the descriptors were released.
The flaw was fixed in 0.6.4, which raises the soft open-files limit, caps open sidecar files below it, and rebuilds listings that dropped an image for a passing error.
