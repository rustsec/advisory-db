# Undelegation callback accepts a buffer that is not the account's undelegation buffer PDA

`cpi::undelegate_account` is called from a program's undelegation callback
(the `process_undelegation` instruction generated by the `#[ephemeral]`
attribute) to re-create a delegated account and copy the committed state
from the delegation program's buffer into it.

Before 0.16.2 it only checked that `buffer` was a signer owned by the
delegation program. It did not check that `buffer` was the
`undelegate-buffer` PDA derived from `delegated_account`, and the generated
`InitializeAfterUndelegation` accounts struct had no seeds constraint on it
either. A buffer that belongs to a different account could therefore be
passed in, and its data would be written into `delegated_account`. This was
exploited against Flash Trade on 2026-07-22 to forge a deposit account and
withdraw about 98k USDC.

0.16.2 checks that `buffer` equals the canonical undelegation buffer PDA for
`delegated_account`, and the `#[ephemeral]` macro now adds a seeds constraint
for `buffer` and an address constraint for `system_program`. Programs built
against an earlier version need to be rebuilt with 0.16.2 or later and
redeployed.
