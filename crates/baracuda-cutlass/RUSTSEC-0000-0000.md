# `PreparedGroupedGemm::run` was a safe function that enqueues asynchronous work outliving the call

`PreparedGroupedGemm::run` uploads packed pointer metadata to the device with an asynchronous host-to-device copy out of the struct's own pinned buffer, then enqueues the grouped CUTLASS kernel, which dereferences the device buffers named in that metadata by raw address. It returned as soon as the work was enqueued. Safe code could drop the `PreparedGroupedGemm` (freeing the pinned buffer under the in-flight DMA) or drop or mutate the input and output device buffers while the kernel was still queued, because nothing tied their lifetimes to completion of the stream work.

Affected: every published version from 0.0.1-alpha.6 through 0.0.1-alpha.126. Fixed in 0.0.1-alpha.137 (alpha.127 to alpha.136 were never published): `run` is now `unsafe fn`; the caller must keep `self` and every device buffer given to `prepare` alive and unmodified until the stream work completes, and for as long as a captured graph can be replayed. This is a breaking change.

Impact: memory corruption or exposure through freed host or device memory from safe code that drops the plan or its buffers before synchronizing the stream. Action: upgrade to 0.0.1-alpha.137 or later. Workaround before upgrading: synchronize the stream before dropping the plan or any buffer used with it. The same release also fixes the `baracuda-driver` / `baracuda-runtime` asynchronous host copies it relies on (see their advisories).
