# Build environment compiled into the library and readable at runtime

The build script of `rustpython-vm` 0.3.0 through 0.5.0 writes every
environment variable of the build into `$OUT_DIR/env_vars.rs`. The crate
compiles that file into `_sysconfigdata`'s `build_time_vars`. That module is
always compiled. No feature turns it off.

Every variable set when cargo ran the build script becomes a string in
`librustpython_vm.rlib`. It is also in every binary that links the library.
Python code running on the interpreter can read them with
`sysconfig.get_config_vars()`.

A binary built in CI with secrets in the environment carries those secrets
in clear text. Registry tokens, cloud credentials and API keys are the usual
ones. Anyone with the binary can read them with `strings` or from Python.

Version 0.6.0 removes the dump and the include. Users of earlier versions
should upgrade, rebuild, and ship new binaries. Every secret that was in the
environment of a past build whose output left the build machine should be
treated as exposed. A `^0.5` or `^0.4` requirement never resolves to 0.6.0.
The requirement itself has to change.

Found by [Bitbison](https://registry.bitbison.io). Its open-source registry
builds crates.io releases in a sandbox. It recorded the build environment
landing in the output of a dependant's build. The leak was then confirmed in
published release binaries of four dependants. The full review is at
<https://registry.bitbison.io/cargo/rustpython-vm>.
