# Query and fragment delimiters can change the parsed URL host

The custom URL parser in gix-url does not end an authority at `?` or `#`. For example, `http://a?@b/repo` is parsed with host `b`, although conforming HTTP URL parsers treat the host as `a` and the remainder as a query.

This disagreement can bypass host-based validation in applications using gix-url. In gix-transport's HTTP redirect handling, parsing a server-controlled Location header can also make the credential-reuse guard retain HTTP Basic credentials for a different actual authority. Exposure depends on processing attacker-controlled URLs or redirects; the credential-disclosure path requires an authenticated HTTP workflow that follows the redirect.

The custom parser was introduced in gix-url 0.33.2. Update to 0.37.1 or later, which terminates authorities at slash, query, and fragment delimiters and adds parser and credential-reuse regression tests.

Reported by GitHub user `shuvamk`, with AI assistance disclosed in the original report.
