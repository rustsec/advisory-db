# `Clone` for `DeviceGroup`, `Seat`, `TabletTool` and `TabletPadModeGroup` can overflow libinput's reference count

`Clone` for `DeviceGroup`, `Seat`, `TabletTool` and `TabletPadModeGroup` calls the matching libinput `*_ref` function, which increments an `int` reference count with no upper bound. `std::mem::forget` is safe, so safe code can clone one of these values and forget the clones until a signed increment overflows inside libinput. Each clone also increments the context's reference count, which can overflow first. Signed overflow is undefined behavior in C.

We confirmed the overflow for `libinput_device_group_ref` and `libinput_seat_ref` with libinput 1.31.1 built with UndefinedBehaviorSanitizer, through another binding (colpetto 0.7.0) that calls these functions from `Clone` in the same way; the sanitizer reports the overflow at the predicted clone, and a run with one clone fewer is clean. We checked these four `Clone` implementations in the `input` 0.10.0 source. A separate run through `input::Libinput::clone` confirmed overflow in the context counter. The tablet functions were checked in the libinput source only.

No fixed version is available.
