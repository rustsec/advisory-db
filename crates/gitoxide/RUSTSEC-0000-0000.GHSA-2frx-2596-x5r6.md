# gitoxide uses Git hashing without SHA-1 collision detection

Affected releases of `gitoxide` use or depend on Gitoxide's unchecked SHA-1 hashing implementation. When an application processes attacker-controlled SHA-1 Git data through the affected hashing code, distinct objects with colliding digests can be accepted under the same object identifier, compromising repository integrity. Exposure requires SHA-1 hashing or object processing; using unrelated APIs alone does not demonstrate an attack.

The vulnerable hashing implementation uses standard SHA-1 without collision-attack detection. The fix migrates hashing to a collision-detecting implementation in `gix-hash` and updates dependent crates to use it. This mitigates known SHA-1 collision attacks; it does not make SHA-1 collision-resistant.

Exploitation requires constructing a collision in suitable Git-formatted data. The upstream demonstration uses colliding PDF files to show the unchecked primitive and is not a direct proof of a collision between valid Git objects.

Upgrade `gitoxide` to `0.42.0` or a later release.

Reported by [emilazy](https://github.com/emilazy), with analysis by [EliahKagan](https://github.com/EliahKagan).
