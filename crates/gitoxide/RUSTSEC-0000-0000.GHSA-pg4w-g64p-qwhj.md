# A symlinked `.gitmodules` can supply configuration from outside the worktree

When loading submodule configuration, `gix` prefers the worktree `.gitmodules` and reads it as an ordinary file. That read follows symbolic links, so a crafted repository can make the submodule APIs parse a file outside the worktree as repository-local configuration.

Consumers can receive submodule names, paths, and URLs from the external file and use them in subsequent operations. The demonstrated impact is configuration injection across the repository boundary; this read alone does not execute commands. Exploitation requires symbolic-link support, an accessible target file, and a workflow that reads submodule configuration.

`gix` 0.82.0 rejects a symbolic link at the worktree `.gitmodules` path before reading it. The corresponding first fixed `gitoxide` release is 0.52.1. Update to a current, non-yanked release; the first fixed `gix` release itself has since been yanked.

Reported by [N0zoM1z0](https://github.com/N0zoM1z0).
