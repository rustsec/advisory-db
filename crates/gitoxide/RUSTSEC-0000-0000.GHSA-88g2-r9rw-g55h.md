# Terminal control characters in repository metadata can spoof command output

The `gix` and `ein` commands included repository-controlled paths and other metadata literally in terminal output. Newlines, backspaces, carriage returns, and ANSI escape sequences can reposition the cursor, conceal output, change terminal state, or make repository data appear to be a trusted warning or error.

For example, `gix tree entries` writes tree-entry filename bytes directly to its output stream. A repository author can use this to present misleading instructions when a user inspects the repository in a terminal. The demonstrated impact is output manipulation and potential social engineering, not automatic execution of the displayed instructions. Effects depend on the terminal's handling of the control sequences.

There is no verified complete patched release. A July 2026 change escaped unsafe paths in `gix index entries`, but `gix tree entries` still writes them literally in `gitoxide` 0.61.0. The original advisory's `<= 0.41.0` bound does not establish that later releases are safe. When examining untrusted repository data, pipe output through a viewer that renders control characters visibly, such as `cat -v`, rather than displaying the raw bytes in a terminal.
