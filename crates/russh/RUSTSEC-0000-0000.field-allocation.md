# SSH message fields allocated before their size is checked

Many of russh's client and server message handlers decoded length-prefixed strings, byte fields and name-lists from the peer into owned `String`, `Vec` or name-list values first and only checked their size and meaning afterwards. This includes the algorithm name-lists in `SSH_MSG_KEXINIT`, which a server parses during the initial key exchange, before any authentication, as well as authentication, service, channel and global request fields.

A peer can fill these fields with oversized or highly fragmented values, for example a name-list of hundreds of thousands of one-letter algorithm names, and make russh allocate far more memory than the packet itself takes. With many concurrent connections this can exhaust the memory of a server process.

From 0.61.0 these fields are read through bounded, borrowing helpers (`take_str`, `take_bytes`, `take_name_list`) that reject values over a per-field limit before anything is allocated.
