# `tokio-tar` `unpack_in` can chmod arbitrary directories by following symlinks

In all versions of the (archived, unmaintained) `tokio-tar` crate, including
0.3.1, `unpack_dir` (`src/entry.rs:491`) checks an already-existing destination
path with `fs::metadata`, which follows symlinks. A crafted tarball containing
(1) a symlink entry pointing to a directory outside the extraction root and
(2) a directory entry of the same name causes the crate to treat the symlink
target as a valid existing directory and apply the archive-specified mode to
it via `set_perms`, silently changing the permissions of a directory outside
the extraction root (verified locally: an outside directory changed from
0o700 to 0o777 while `unpack` returned `Ok`).

This is the same flaw that was fixed in the `tar` crate as CVE-2026-33056
(GHSA-j4xf-2g29-59ph, RUSTSEC-2026-0067) and recorded for `astral-tokio-tar`
as RUSTSEC-2026-0113; it has not previously been recorded for the `tokio-tar`
package itself. The direct effect is limited to directory permissions;
individual file permissions cannot be modified via it.

The `tokio-tar` crate is archived and no longer maintained (and is already
the subject of RUSTSEC-2025-0111 for a PAX parsing issue). No patched version
exists; users should migrate to a maintained tar implementation.
