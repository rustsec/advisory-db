# Dilithium verification accepts non-conforming signatures with the `avx2` feature

With the default `avx2` feature on x86_64 and a CPU that supports AVX2,
`pqcrypto-dilithium` verifies signatures with PQClean's AVX2 implementation of
Dilithium. That implementation predates two upstream fixes
([pq-crystals/dilithium#113](https://github.com/pq-crystals/dilithium/issues/113),
3 June 2026), the same ones described in RUSTSEC-2026-0586 for `pqcrypto-mldsa`:

- the verifier does not check that the infinity norm of `z` is below
  `γ1 − β`, so it accepts signatures that the crate's own portable
  implementation rejects;
- `use_hint_avx()` mishandles a boundary case, so one class of valid
  signatures is rejected.

Creating an accepted out-of-bound signature requires the private key. The
practical effect is that verification results differ between this crate with
AVX2 and the same crate without it.

Tested on version 0.5.0: for each of dilithium2, dilithium3 and dilithium5, 20
signatures with `z` out of bound are accepted with AVX2 and rejected by the
portable code, and 2 valid signatures that exercise the `use_hint` boundary
are rejected with AVX2 and accepted by the portable code. This crate
implements a pre-standard version of the scheme, so the Wycheproof ML-DSA
vectors do not apply; the test signatures are built with the crate's own
signer.

The crate is unmaintained (see RUSTSEC-2024-0380) and no patched version is
expected. Disabling the `avx2` feature avoids the affected code.
