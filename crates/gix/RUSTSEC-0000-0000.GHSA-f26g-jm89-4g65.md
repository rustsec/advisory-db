# A partial local override can allow an untrusted submodule update command

`gix_submodule::File::update()` is intended to reject `update = !<command>` values from an untrusted `.gitmodules` file. Its provenance check instead accepts the command whenever any same-named local submodule section exists, even if that section does not contain the winning `update` value.

For example, initializing a benign submodule can create a local section containing only its URL. If a later repository update adds a shell command to `.gitmodules`, the local section satisfies the guard while the value lookup falls back to the attacker-controlled command. `gix::Submodule::update()` exposes the same result.

The APIs return an update strategy; they do not themselves execute the command. An application that trusts the guard and executes the returned `Update::Command` can run attacker-controlled commands with the user’s permissions. The advisory’s demonstrated `gitoxide` CLI did not implement submodule-update execution.

`gix-submodule` 0.29.0 checks the metadata of the section that actually provides the update value. `gix` 0.82.0 incorporates that fix. Upgrade the affected library or its consuming application, using a current non-yanked `gix` release.

Reported by [swgillespie](https://github.com/swgillespie).
