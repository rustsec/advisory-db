# An SSH URL username can inject options and load an attacker-controlled configuration

The SSH transport checked URL hosts and paths for values that could be interpreted as command-line options, but did not reject a username beginning with `-`. For an address such as `ssh://-Fconfigfile@example.com/repo`, the external `ssh` program could interpret the combined username and host as an `-F` option rather than a destination.

Known code execution requires the victim to connect using the crafted URL while the current directory contains the specially named attacker-controlled SSH configuration file, such as `configfile@example.com`. Its `ProxyCommand` setting can then execute a command with the victim application's permissions. Other injected options may create or append to a file in the current directory. The URL alone is not sufficient for the demonstrated code-execution attack.

`gix` consumers are exposed when using the affected SSH transport; `gitoxide` exposes it through commands such as `gix clone`. `gix-transport` 0.42.0 rejects unsafe usernames before launching SSH. `gix` 0.62.0 and `gitoxide` 0.35.0 require the fixed transport. Avoid connecting to attacker-controlled SSH URLs from an untrusted working directory with affected versions.
