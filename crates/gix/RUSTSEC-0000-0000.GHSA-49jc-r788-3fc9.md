# Reserved Windows device names can block cloning or spoof console output

Gitoxide does not reject reserved Windows device names before reading loose references or checking out files. A repository containing a reference such as `CON` or `CONIN$` can cause a Windows clone to read from a device and block on console input. A checked-out path such as `CON` or `CONOUT$` can direct attacker-controlled file contents to the console instead of an ordinary worktree file.

Names are case-insensitive and some extensions or other suffixes preserve their device meaning. Console writes can appear to be trusted application messages and mislead a user into following attacker instructions. Other effects depend on the devices available, configuration, and permissions; direct arbitrary code execution or data exfiltration is not established by these examples.

This issue affects Windows workflows that fetch refs or materialize paths from untrusted repositories. Update to gix 0.63.0 or later. The fixing release validates path components and rejects reserved device names before the relevant disk access.

Reported by Eliah Kagan; remediation by Byron.
