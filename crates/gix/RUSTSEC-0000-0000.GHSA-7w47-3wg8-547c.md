# Checkout paths can escape the worktree and install hooks

Checkout does not adequately validate tree and blob names before converting them to filesystem paths. An untrusted repository can use `..`, embedded separators, or `.git` names to create files outside the destination worktree or inside Git metadata.

A malicious clone can install an executable hook, which runs when the victim later performs the corresponding Git operation. It can also place other files in writable locations where later processing may execute them. The immediate demonstrated result is attacker-controlled file creation; code execution depends on a subsequent operation or consumer of those files and occurs with the victim process's permissions. Files created outside the destination can remain even if cloning fails and the destination is removed.

Ordinary traversal applies across platforms. Additional aliases include backslash separators and NTFS alternate-data-stream or short-name forms on Windows, and `.git` case or collation variants on affected filesystems, including HFS+. Exposure requires cloning with checkout or invoking checkout APIs on untrusted trees.

Update to gix 0.63.0 or later. The fixing release rejects unsafe components during tree-to-index conversion and worktree path traversal, and passes validation options through checkout.

Reported by Eliah Kagan; remediation by Byron.
