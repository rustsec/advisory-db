# Incremental checkout can write through a symlink on Windows

On Windows, non-exclusive checkout can write through an existing terminal symlink when an index entry is materialized as a regular file. Intermediate directory checks do not cover that final component, the debug-only check follows the symlink before examining its type, and the filesystem no-follow helper is effective only on Unix.

A downstream application using incremental checkout with `destination_is_initially_empty: false` can therefore overwrite the symlink's target outside the destination worktree with the permissions of the process. The demonstrated case requires an existing symlink and a colliding regular-file entry. It is a library-API issue; the original report did not demonstrate it through the shipped clone/checkout CLI paths, whose destinations were initially empty.

Update to gix 0.86.0 or later. Incremental checkout now enables terminal-symlink validation on Windows; forced replacement removes the link itself immediately before creating replacement content. Direct worktree-stack users must enable `Stack::enable_terminal_symlink_check()` before traversal to use the new validation.

Reported by GitHub user `scadastrangelove`.
