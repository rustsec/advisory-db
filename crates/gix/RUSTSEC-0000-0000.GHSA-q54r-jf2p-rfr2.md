# Reduced-trust configuration can disable filesystem path protections

`gix` read `core.protectHFS`, `core.protectNTFS`, and `gitoxide.core.protectWindows` without applying its configuration-section trust filter. Repository-local configuration rejected for other security-sensitive settings could therefore disable these filesystem path protections even when the repository was opened with reduced trust.

An attacker who controls an untrusted repository's configuration and tree entries can bypass the intended validation of filesystem-specific aliases of `.git`. On affected filesystems, later operations that materialize such paths can modify repository metadata, including hooks or configuration. Execution of an overwritten hook depends on a subsequent operation that invokes it.

The configurable path-protection reader first shipped in `gix` 0.63.0, not 0.88.0 as stated in the original advisory. Version 0.90.0 applies the section filter to all three settings, including the early reference-store protection setting. Versions earlier than 0.63.0 are unaffected by this configuration-reader vulnerability.

Reported by zx ([@manus-pi](https://github.com/manus-pi) and [@manus-use](https://github.com/manus-use)).
