# Unvalidated submodule names can redirect repository resolution outside `.git/modules`

Submodule names read from `.gitmodules` are reused as filesystem paths under `.git/modules` without validation. A name containing parent-directory components can escape that directory, causing `Submodule::state()` to inspect, and `Submodule::open()` to open, another repository chosen by the attacker. The `gitoxide` submodule-listing command also reaches these APIs.

The target must be an existing valid Git repository reachable by the process, and the victim must use a consumer that inspects or opens the crafted submodule. The demonstrated effect is repository confusion and access to the wrong repository; this behavior alone does not demonstrate command execution or transmission of its data to the attacker.

`gix` 0.82.0 validates submodule names before deriving the Git directory. The corresponding first fixed `gitoxide` release is 0.52.1. Update to a current, non-yanked release; the first fixed `gix` release itself has since been yanked.

Reported by [N0zoM1z0](https://github.com/N0zoM1z0).
