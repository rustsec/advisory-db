# Agent-controlled Git configuration can escape the push broker boundary

Versions 0.2.2 and 0.2.3 of `agent-guard-broker` allowed an
agent-writable Git repository to influence a credential-bearing Git process.

The broker preview resolved `remote.<name>.url`, while execution passed the
remote name to `git push`. Git could therefore honor an agent-controlled
`remote.<name>.pushurl` and push to a different destination than the preview
and receipt identified. The remote lease was also derived from the previewed
URL and then applied to the different push destination.

The same credential-bearing process ran in the agent-controlled repository
and loaded its hooks and execution-bearing Git configuration. An agent able to
write the repository could install a `pre-push` hook or related configuration
and execute arbitrary code with the broker process's credentials, even when
the subsequent push was rejected.

Version 0.2.4 resolves exactly one push URL and passes that literal URL to all
network operations. It performs those operations from a broker-owned bare
snapshot that excludes repository configuration, hooks, alternates, and
replace refs; uses a validated host-owned Git configuration; clears Git-specific
environment variables; disables hooks; and restricts allowed protocols.
