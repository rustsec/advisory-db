# Default key exchange provides no confidentiality

Versions of `qssh` before 0.4.2 default to the `FalconSignedShares` key
exchange, which authenticates the peers with Falcon signatures but derives the
session key from values transmitted in cleartext. A passive network observer
who records the handshake can reconstruct the session key and decrypt the
session. Authentication is not affected.

An ML-KEM exchange existed in the crate, but the `qssh` client hardcoded the
default algorithm, so it could not be selected from the command line.

Version 0.4.2 defaults to ML-KEM-1024 and honours the configured algorithm.
Users should upgrade and treat sessions established under the old default as
not confidential. All earlier versions are yanked.
