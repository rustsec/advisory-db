# SQL injection through the type name of a cast in `select`

The type name after `::` in a `select` cast (for example
`?select=price::text`) was written into the generated SQL statement as the
client sent it. The parser accepted spaces in that position, so any client --
including an anonymous one when an anonymous role is configured -- could append
SQL keywords and identifiers to the statement's SELECT list.

The injectable characters are limited to letters, digits, `_`, `$` and spaces,
so no second statement can be stacked, and the statement still runs as the
request's database role, under its grants and row-level security. No way to
read data the role could not read anyway has been found, but one is not ruled
out.

Version 2.4.1 parses a cast as a single type name (or one of the SQL
standard's multi-word type names, written in the standard's spelling) and
refuses anything else with 400 `PGRST100`. Upgrade `postrust-core` (and with it
`postrust-server` or `postrust-lambda`) to 2.4.1 or later; 3.0.0 is also fixed.
The Cloudflare Worker build, `postrust-worker`, is fixed in 1.0.1.
