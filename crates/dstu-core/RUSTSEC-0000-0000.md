# `crypto_secretbox` / `crypto_secretstream` ciphertext can be extended or shortened without detection

The Kalyna-GCM used by `crypto_secretbox` and `crypto_secretstream` padded a partial final
ciphertext block with `0x80 00..` before GHASH and put the padded length into the length block, and
the wrappers' associated data did not carry the ciphertext length. A ciphertext `C` and
`C || 80 00..` (up to the block boundary) therefore had the same tag.

Without the key, an attacker can append `80 00..` to a ciphertext whose length is not a multiple
of 32 (decryption then returns 1-31 extra pseudo-random bytes), or remove trailing `0x80`/`80 00..`
bytes from a ciphertext or a non-final stream record (decryption returns the plaintext with bytes
deleted). The `uacrypt` CLI's `encrypt`/`decrypt` are affected the same way.

0.4.0 binds the true ciphertext length into the associated data, follows DSTU 7624:2014 §12 for the
GCM length block, adds a format-version byte, and rejects non-final stream records that are not
exactly 8192 bytes. This is a breaking format change: data written by 0.3.x cannot be opened by
0.4.0. Decrypt it with the release that wrote it, treat the result as unauthenticated, and
re-encrypt with 0.4.0.
