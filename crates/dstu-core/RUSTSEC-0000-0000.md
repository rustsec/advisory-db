# `hazmat` Kalyna-GCM / GMAC return the GHASH key as the tag for empty input

DSTU 7624:2014 §12.1 requires `|O| + |M| >= 1`. Earlier releases accepted Kalyna-GCM with empty
AAD and empty plaintext, and Kalyna-GMAC over an empty message. The tag is then `E_K(0)`, which is
the GHASH key `H`; Kalyna-GCM applies no nonce-derived mask to the tag, so nothing hides it. Anyone
who observes such a tag learns `H` for that key and can forge tags for other messages of a length
they have seen a tag for under the same key.

Only the `hazmat::kalyna_gcm` and `hazmat::kalyna_gmac` modules (and the `uacrypt` CLI's
`kalyna-gcm`/`kalyna-gmac` commands) are affected. The `crypto_*` API never reaches this input.

0.4.0 rejects that input (`GcmError::EmptyInput`, `GmacError::EmptyMessage`); either the AAD or
the data alone may still be empty.
