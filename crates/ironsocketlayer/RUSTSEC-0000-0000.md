# Name-constraint bypass, denial of service and truncation in ironsocketlayer 0.1.0

ironsocketlayer 0.1.0 has five issues, fixed in 0.2.0:

- A dNSName with a trailing dot (`victim.evil.com.`) escaped an excluded
  name-constraint subtree.
- iPAddress constraints were applied per address family: an IPv6 address
  escaped an IPv4-only permitted list, and an IPv4-mapped IPv6 address
  escaped an excluded IPv4 subtree.
- The duplicate-extension check before signature verification was
  quadratic: a 128 KiB certificate cost about 350 ms per parse.
- Path search could spend 100 signature verifications on a crafted chain,
  reachable by any client of a server that accepts client certificates.
- `TlsStream::read` returned `Ok(0)` when the transport closed without
  close_notify, hiding truncation.

The first two need a certificate from a name-constrained CA that the victim
trusts; the denial-of-service issues need no credentials.

0.2.0 is a minor version because it also changes public configuration and
report structs; see its CHANGELOG.
