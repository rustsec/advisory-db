# Elevated Windows administrators can incorrectly trust other users’ repositories

On Windows, the ownership check in `gix-sec` attempts to account for directories owned by the Administrators group. It checks the owner of the running process or thread token where it should check the directory owner. When run with an elevated administrative token, this can incorrectly mark a repository controlled by a different local user as trusted.

An attacker with a limited local account can configure a repository in a location an elevated administrator may use or discover. A consuming application that relies on this ownership result can then honor repository configuration that launches commands, such as `core.sshCommand`, with administrative privileges. The issue requires Windows, an unfiltered administrative token, a repository controlled by another local user, and a workflow that uses the resulting trust. Merely cloning a repository does not copy its local configuration or hooks and is not the demonstrated attack.

`gix-sec` 0.13.3 compares the actual directory owner with the current token user and performs the administrator-group check against that directory owner. Upgrade `gix-sec` or its consuming application. Running without elevation avoids the vulnerable administrator case.

Reported by [EliahKagan](https://github.com/EliahKagan).
