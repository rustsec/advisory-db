# Request smuggling after a WebSocket upgrade, and two forwarded-fact spoofing defects

Three defects, fixed together in 0.6.3. Each has its own affected versions and conditions.

**A request smuggled after a WebSocket upgrade** (0.6.0 to 0.6.2, feature `ws`). Input the HTTP
engine had not yet taken, in the read that carried the upgrade request, was fed back to the HTTP
engine after the `101` and parsed as a new request. A client could place a request behind about
64 KiB of WebSocket frames and have it reach `HttpService::call`; behind a trusted proxy, the
smuggled request's own `X-Forwarded-For` was believed. It needs a read size above net-io's default
16 KiB.

**`X-Forwarded-Host` and `X-Forwarded-Proto` believed for an RFC 7239 source** (0.3.0 to 0.6.2).
With `ForwardedSource::Forwarded`, `MissingHeader::UsePeer`, and `trust_host` or `trust_scheme` on,
a request from a trusted peer that carried no `Forwarded` element had those fields believed at
`HttpService::head`, so a client behind an RFC 7239 proxy chose the host and scheme seen there.

**Plain clients reported as https behind PROXY v2** (0.4.0 to 0.6.2). With `trust_scheme` on a
PROXY protocol listener, any PROXY v2 SSL TLV marked the client `https`, including a TLV without
the `PP2_CLIENT_SSL` bit, which proxies such as HAProxy send for plain connections too.

Versions 0.3.0 to 0.6.2 are yanked.
