# Following a symbolic-linked write lock file enables arbitrary file truncation

When getting the write lock, we open and truncate the write lock file.  If the
write lock file happened to be a symbolic link, then we open the target of the
symbolic link and truncate that.

Most users will not be affected by this as certificate directories are not
shared between users.

This issue has been fixed by checking that the write lock is not a symbolic
link.
