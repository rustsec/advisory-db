# Unknown schema ids grow the Avro schema cache without bound

In Confluent wire-format mode, the default, the deserializer in affected versions caches a negative entry for each schema id the registry answers with 404, and never removes one. The id is four bytes of each record, so a producer writing records with distinct unknown ids grows the cache by one entry per id for the life of the process. Each new entry also copies the whole cache under the lock that schema lookups wait on.

Memory grows with every distinct unknown id and is never released. Under a 256 MiB memory limit, a pipeline on 0.3.0 was killed after 130,000 unknown ids, and schema resolution slows on the way there for every pipeline thread that needs a fresh view of the cache. An attacker needs produce access to a topic the pipeline reads. `mode: raw` and `mode: single_object` are not affected.

The flaw was corrected in 0.4.0 (commit `2b877466`). A write to the cache drops negative entries past `negative_cache_ttl`, and the cache holds at most 1,024 negative entries, replacing the oldest when full.
