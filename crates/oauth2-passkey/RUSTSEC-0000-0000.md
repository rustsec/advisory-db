# Passkey registration can overwrite another user's registered credential

Passkey registration did not check that a credential ID was unused, and stored
the credential ID supplied by the client (`rawId`) without verifying it against
the credential ID in the attested credential data. Credentials were written with
an upsert keyed on the credential ID on all storage backends (SQLite,
PostgreSQL, MySQL/MariaDB).

A user who knows the credential ID of another user's passkey could complete a
registration with their own authenticator while submitting that credential ID
as `rawId`. The stored credential was replaced with the new public key and
re-assigned to the requester's account, so the victim could no longer sign in
with that passkey. New-user registration does not require authentication, and
credential IDs can be obtained from the unauthenticated authentication start
endpoint when a username is supplied. The requester does not gain access to the
victim's account.

Fixed in 0.6.2, which rejects a credential ID that is already registered, takes
the credential ID from the attested credential data and requires the
client-supplied `id` and `rawId` to match it, and stores credentials with a
plain `INSERT`. `oauth2-passkey-axum` 0.6.x users receive the fix with
`cargo update -p oauth2-passkey`.
