# Submodule traversal validation and inherited trust can expose the wrong repository

The submodule-name validator checks only the first `..` occurrence. If that occurrence is embedded in a harmless name, such as `a..b`, later parent-directory components are not checked. A name such as `a..b/../../../target.git` can therefore pass validation while traversing outside the intended submodule directory.

In affected `gix` versions, the high-level submodule APIs also build paths from unvalidated names, and `Submodule::open()` inherits the superproject’s Git-directory trust instead of deriving trust for the opened submodule repository. A consumer that opens the crafted submodule can thus obtain a different, existing Git repository with excessive trust. Configuration in that repository may contain credentials, but the demonstrated API access does not by itself transmit those credentials to the attacker; disclosure or command execution depends on what the consuming application subsequently does.

`gix-validate` 0.11.1 checks every path component for parent traversal. `gix` 0.82.0 applies validation to submodule Git-directory derivation and recomputes trust when opening submodule repositories. Upgrade to a current, non-yanked `gix` release. Applications that use `gix-validate` directly should also update it.

Reported by [kodareef5](https://github.com/kodareef5).
