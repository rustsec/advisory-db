# Unauthenticated remote stack-overflow DoS: recursive built-in decoders bypass the decoding DepthGauge

The binary decoder in `async-opcua-types` bounds recursion with a `DepthGauge` / `DepthLock` (`src/encoding.rs`, default `max_depth = MAX_DECODING_DEPTH = 10`), but `DepthLock::obtain()` is consulted at only two sites (`extension_object.rs` and the `VARIANT` branch of `variant/mod.rs`). Several recursive built-in `BinaryDecodable` implementations recurse without obtaining the lock, so an attacker-supplied deeply-nested value recurses without bound and overflows the stack, aborting the process (a Rust stack overflow aborts regardless of the `panic` setting). This is an incomplete fix of CVE-2022-25903, whose remediation gauged only `ExtensionObject` and nested `Variant`.

Unguarded recursion cycles (default OPC-UA binary encoding):

- `DiagnosticInfo` self-recursion on the `HAS_INNER_DIAGNOSTIC_INFO` branch (`diagnostic_info.rs`).
- `Variant` <-> `DataValue` mutual recursion: the `DATA_VALUE` branch of `Variant::decode` (`variant/mod.rs`) is unguarded while the adjacent `VARIANT` branch is, and `DataValue::decode` (`data_value.rs`) recurses back into `Variant::decode`.
- `Variant` -> `DiagnosticInfo` (`variant/mod.rs` `DIAGNOSTIC_INFO` branch), feeding the first cycle.

Reachability (unprivileged, default binary encoding):

- A malicious OPC-UA server crashes any client: `ResponseHeader.service_diagnostics` is a `DiagnosticInfo` decoded on every response.
- A `SecurityPolicy::None` server endpoint is crashed by an unauthenticated client sending a `Variant`/`DataValue`-carrying request (the request body is decoded before session validation).

Remediation: obtain a `DepthLock` on every recursive built-in decode (`DiagnosticInfo`, `DataValue`, and the `DATA_VALUE`/`DIAGNOSTIC_INFO` branches of `Variant::decode`), ideally via a centralised guard. Related unbounded recursions over attacker-supplied structure exist in `src/custom/type_tree.rs` (cyclic `parent_ids` chain) and the `DynamicTypeLoader` field decode.

Reported by Copperfault LLC (source review + benign unit-test validation). Affects the `opcua` crate lineage as well.
