# Records with a DNS class other than the query's marked secure without being validated

When DNSSEC validation grouped a response's records into RRsets, it did not take the DNS class into account, and records of a class other than IN were left out before signatures were checked. If the IN records validated, the records of other classes (such as CH or HS) were marked secure too.

An attacker who can answer or modify DNS responses can add forged records of another class to a response and have them returned as validated. A forged DS record of another class can also get past validation, which lets any DNSKEY for the child zone be accepted and any answer from that zone be forged. How much this matters depends on how the application treats records of an unexpected class.

This affects DNSSEC validation through `DnssecDnsHandle` when built with `dnssec-ring` or `dnssec-aws-lc-rs`.

The fix rejects a whole response if any record in its answer, authority or additional section has a class different from the query's.
