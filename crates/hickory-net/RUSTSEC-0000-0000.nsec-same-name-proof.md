# Unsigned NSEC or NSEC3 record used in a nonexistence proof when another record at the same name is signed

When DNSSEC validation collected the NSEC and NSEC3 records from a response's authority section to check a denial of existence, it kept a record if any authority record with the same owner name had validated, not only if that record itself had. A response could therefore pair a correctly signed record with a forged NSEC or NSEC3 record of the same owner name, and the forged record was used in the nonexistence proof.

An attacker who can answer or modify DNS responses can use this to get a forged NXDOMAIN or NODATA answer accepted as secure.

This affects DNSSEC validation through `DnssecDnsHandle` when built with `dnssec-ring` or `dnssec-aws-lc-rs`.

The fix keeps an NSEC or NSEC3 record only when its own signature validated.
