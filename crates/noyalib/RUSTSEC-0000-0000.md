# Entry points disagree on trailing documents and parser policies

### Impact

`from_str_borrowing` returned the first document and ignored a second document or a trailing syntax error, where `from_str` refuses them, so the same bytes read differently through the two APIs. `from_str_borrowing_with_config` ignored every parser policy, `DenyAnchors` included, and several loaders skipped the whole-document `check_value` hook. A caller that validated input through one entry point and consumed it through another could act on different data than it checked.

### Patches

Fixed in 0.0.55. Every entry point refuses trailing content and runs the same policy checks.

### Workarounds

Parse and consume untrusted input through the same entry point, and prefer `from_str`.
