# Resource limits not enforced on several sibling paths

### Impact

Several paths enforced fewer limits than `from_str`. `read_with_config` read the whole reader before checking `max_stream_bytes`. The CST stream and `cst::format` ignored `max_documents`. `!include` gave each included level the full `max_depth`, read whole files before the byte budget applied, and blocked forever on a FIFO. The typed path estimated alias expansion at 8 bytes a node with no ceiling. `Spanned<T>`, `YamlDecoder` and the unknown-alias suggestion had quadratic costs. Each let a small input cost far more memory or time than the configured limits allow.

### Patches

Fixed in 0.0.55. A parity test now checks every limit on every entry point, and each listed path enforces them.

### Workarounds

Cap input size before parsing, and avoid `!include`, the CST stream and `Spanned<T>` on untrusted input.
