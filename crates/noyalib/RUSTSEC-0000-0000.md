# Serializer output can add keys or split values on read-back

### Impact

Several serializer paths wrote untrusted strings so that reading the output back gave different data. In flow style, a string holding `,` `[` `]` `{` or `}` was written unquoted, so `"viewer, admin"` came back as two items and a flow-mapping value could add a key. Formatting hints were carried in a reserved `__noya_` tag namespace that documents could reach with `%TAG`, so re-serialising a hostile document could add keys through a comment hint. Comment text with line breaks and a string key `<<` had the same effect.

### Patches

Fixed in 0.0.55. Flow strings with indicators are quoted, formatting hints can only come from the `fmt` wrapper types, comments with line breaks become several comment lines, and `<<` keys are quoted.

### Workarounds

Write untrusted values in block style, and do not re-serialise parsed documents that may carry tags.
