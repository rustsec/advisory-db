# `keyword_token` treats arbitrary bytes as UTF-8

`keyword_token` is a safe public function. It calls `str::from_utf8_unchecked` on the caller-supplied `&[u8]` before looking the word up. Invalid UTF-8 is undefined behavior.

The report was filed against the copy vendored in `libsql`. The same function is published as `libsql-sqlite3-parser`. It is in every crates.io release of that crate, from 0.11.0 through 0.13.0, and 0.13.0 still uses `from_utf8_unchecked`. No patched release exists. The `libsql` package tarball itself does not contain this function.
