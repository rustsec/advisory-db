# Cached symlink prefixes can redirect checkout writes outside the worktree

During checkout, a cached leaf can become a parent directory without repeating the filesystem validation performed for a new directory. A crafted tree with conflicting symlink and directory entries can therefore reuse an attacker-controlled symlink as a parent and create a subsequent symlink outside the worktree, including in `.git/hooks`.

The attacker must supply repository contents that a victim checks out and choose an existing destination directory writable by that victim. The demonstrated primitive is arbitrary symlink creation in such directories. If the link installs a hook or another file that is later executed, this can lead to code execution with the victim’s permissions.

`gix-fs` 0.21.1 revalidates cached leaves through the delegate’s directory-creation and collision checks before using them as parents. Update `gix-fs` or the application that depends on it.

Reported by [LawnGnome](https://github.com/LawnGnome). Found through Project Glasswing with Claude Mythos; the reporter states that a human verified the vulnerability.
