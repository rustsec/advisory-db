# Forced checkout can reuse a stale symlink prefix and modify paths outside the worktree

A filesystem stack could retain the belief that a cached terminal entry was a directory after forced checkout replaced it with a symlink. A later symlink entry beneath that cached prefix then bypassed leading-directory validation and resolved outside the intended worktree.

The demonstrated checkout requires `overwrite_existing = true` on Unix and a delayed-symlink phase that reuses the stack from file checkout, as in a single-worker checkout. An attacker-controlled tree can create symlinks outside the worktree and replace existing external files or directories, including recursive deletion during collision handling. Planting a repository hook can lead to code execution if a later operation invokes it. The reproduction does not establish arbitrary regular-file content writes outside the worktree, and ordinary clone behavior is not the demonstrated trigger.

Version 0.23.0 removes cached directory delegate state when a component becomes terminal and validates terminal requests before later descent. This also closes the stale-prefix bypass after the earlier GHSA-f89h-2fjh-2r9q fix. Avoid forced checkout of untrusted trees with affected versions.

Reported by @euriconicacio.
