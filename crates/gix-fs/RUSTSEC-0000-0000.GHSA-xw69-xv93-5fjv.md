# Windows symlink target probes can disclose NTLM authentication material

On Windows, `gix_fs::symlink::create()` determined whether to create a file or directory symlink by following the target with a filesystem metadata query. An attacker-controlled repository can contain a symlink whose target is a UNC network path, or a local symlink chain leading to one. Probing that target can open an SMB connection to the attacker's server and disclose Windows NTLM authentication material.

Exposure requires a checkout that creates symlinks, Windows permission to create them, and network access to the attacker's SMB endpoint. This does not disclose a plaintext password; the captured authentication response may enable subsequent cracking or relay attacks, depending on the environment.

Version 0.24.1 avoids target-following probes for separator-prefixed targets and checks indirect targets with bounded, no-follow traversal. Disabling symlink checkout is a workaround for workflows that do not need symlinks.

Reported by zx ([@manus-pi](https://github.com/manus-pi) and [@manus-use](https://github.com/manus-use)).
